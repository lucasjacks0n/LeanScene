Why it’s fast enough for a browser. Running a CLIP model on every frame of a video is far too slow, so the video is first cut into shots and MobileCLIP looks at one frame per shot. On the two-hour film we measured, that was fewer than 1 frame in 100. It only pays off if finding the shots is cheap: LeanScene does 115× less work per frame than TransNet V2, the standard model, so it can read every frame right here in the tab.

Questions

Is my video uploaded anywhere?

No. It is decoded, split into shots and searched inside this browser tab. The only things downloaded are the two models.

What gets downloaded?

LeanScene is 1.6 MB and comes with the page. MobileCLIP-S0, Apple's image-and-text model, is an 88 MB download on your first visit; the browser caches it after that. Both run on your graphics card when the browser supports WebGPU, otherwise on the CPU.

How good is the cut detection?

LeanScene scores higher than TransNet V2 on all three standard benchmarks while doing 115× fewer operations per frame. See the benchmarks above → A paper describing the model and the evaluation is in preparation.

What will the search miss?

Each shot is represented by one frame, usually from its middle, so something that only appears briefly at the start or end of a long shot may not be found. Searches work best as short descriptions of what is visible.

Can I use this in my own project?

Yes. LeanScene is open source: pip install git+https://github.com/lucasjacks0n/LeanScene or npm install leanscene. Code, weights and training labels on GitHub →
